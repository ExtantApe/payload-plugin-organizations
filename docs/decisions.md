# Decisions

Dated decisions for this repo, newest last.

- 2026-11-22: created from the ops starter kit, area `co-plugins`.
- 2026-11-22: first version built for the Captive Origins site, following its decisions: organizations with Coordinator, Member and Viewer levels; a pending organization's first Coordinator approved by admins, with no time limit; a domain list that ships in the plugin and that the host can extend; a university grouping people only after staff set it up from ROR; a minor never joining any organization. The plugin stays agnostic: the minors rule is the host's `refuseMember` veto, not built in.
- 2026-11-22: following EXTANT APE's review of the positions and sharing PRs: hooks fail closed on anything but an exact `true`, `refuseMember` is required (`false` opts out), re-activation and widening go back through the approver gate and the veto, nobody approves themselves, deletes always throw, changes go to an append-only `organization-events` history, ids are keyed by collection, text has length limits, and private notes are hidden from members.
- 2026-11-22: the plan in the package description (importers, suggestions) is cut to this first version: collections, levels, the domain list and matcher, and the picker. Importers and user suggestions are later pull requests.
- 2026-11-23: following the review of the first pull request: nobody approves, reopens, closes or widens an organization they made or belong to, on the membership path and for ROR ids and domains too; the veto runs when a person accepts and not when someone else invites them, so inviters can't tell which accounts it covers (it still runs at invitation for server code and for a person inviting themselves); `refuseMember` must be a function or exactly `false`; the plugin refuses to start on a database without transactions unless `allowWithoutTransactions` is set; bulk updates and deletes on its collections are refused; public suffixes can't be domains; `matchOrganizations` takes the user (re-read from the database), needs a verified email and runs the veto; the picker respects the editor's read access.
- 2026-11-23: second review round: a removed row still counts as belonging, so leaving then approving is refused; level changes on invited rows are refused for non-server callers; reopening asks the veto about active people only; an unknown person or an unseen duplicate gets the generic invite refusal, and hosts must use ids nobody can guess; `matchOrganizations` re-reads the user; `tldts` is pinned exactly. Old commit messages stay as they are; current files and new messages carry no Captive Origins ids.
- 2026-11-23: a level change on an active row that the veto refuses reads the same to the changer as any other refused level change; server code still sees the reason.
- 2026-11-23: third review round: only a place a person accepted (or an organization they made) counts as belonging, so leaving doesn't undo it and an unaccepted invitation can't lock approvers out; closing an organization skips the made-or-belongs check, because it takes access away; reopening and widening keep it. This replaces the 2026-11-23 line about a removed row always counting.
- 2026-11-23: asked whether to close the level-change oracle now or later, the owner chose "Fix it now (Recommended)". A promotion of an active member is held as a pending level and the veto runs when the person accepts, the same shape as the positions plugin; a demotion is immediate and skips the veto because it only takes access away; server code still promotes at once. `allowWithoutTransactions` must be exactly `true` or `false`, or the plugin won't start.
- 2026-11-23: a withdraw and an accept on the same row at the same moment end in one success and one plain refusal (403). Every change to a membership first writes the row once to take its lock, the same way the positions plugin does, and a database write conflict (code 112, `WriteConflict`, the `TransientTransactionError` label, also as a nested cause) becomes the plain refusal instead of a raw error.
